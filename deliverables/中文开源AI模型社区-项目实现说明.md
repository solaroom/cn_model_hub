# 中文开源 AI 模型社区项目实现说明

本文档用于课程大作业汇报 PPT 的内容整理。整体写法按“项目已经实现了什么”来组织，尽量避免过细的接口说明，也不夸大当前没有完全做成的能力。

## 一、项目定位

本项目的主题是“中文开源 AI 模型社区”。它可以理解为一个面向中文模型生态的轻量级 Hugging Face Hub，重点解决模型、数据集和在线 Demo 在课程展示场景中的统一管理问题。

项目围绕中文大模型资源展开，提供模型托管、数据集管理、在线 Demo、中文搜索、快速评测、排行榜、实验追踪和智能助手等能力。相比单纯的文件上传系统，本项目更强调“资源社区”和“模型生命周期管理”：用户不仅可以上传模型文件，还可以查看模型介绍、管理版本、启动演示、运行快速评测，并通过搜索或智能助手找到需要的资源。

从课程作业角度看，本项目覆盖了一个 AI 模型社区平台的主要功能方向：资源发布、资源浏览、模型运行展示、评价排名、基础管理和部署演示。

## 二、结合课程大作业要求的完成情况

课程大作业通常希望实现一个面向 AI 模型的开源社区或资源管理平台，核心关注点包括用户管理、模型管理、数据集管理、搜索展示、在线体验、评价或排行榜，以及一定的系统部署能力。

当前项目已经实现了较完整的平台雏形，主要体现在以下几个方面：

1. **用户与权限体系**

   平台支持用户注册、登录、个人主页、Token 管理和基础权限控制。资源仓库可以区分公开与私有，后端在读取、上传、删除、运行等关键操作中会进行权限判断。

2. **模型资源管理**

   平台支持创建模型仓库、上传模型相关文件、展示 README 模型卡片、查看文件树、下载文件和查看提交记录。对于大模型常见的大文件，系统引入对象存储和 LFS 风格处理，避免把模型权重直接存入数据库。

3. **数据集资源管理**

   平台支持数据集仓库的创建、文件上传、README 展示和基础预览。当前演示数据集中包含 C-Eval 相关样本，用于说明中文评测数据集在平台中的托管和使用方式。

4. **中文搜索与资源发现**

   项目接入了 Meilisearch，用于模型、数据集和 Space 等资源的检索。搜索逻辑中加入了中文模型常见别名和关键词扩展，例如 Qwen/千问、GLM/智谱等。搜索服务不可用时，后端也设计了数据库回退查询机制。

5. **在线 Demo 与模型运行**

   平台提供简化版 Space / Demo 能力。模型仓库或 Space 仓库可以通过后端运行时 materialize 文件，再启动 Python/Gradio 应用，并在前端页面中嵌入展示。当前重点支持 Qwen2.5-0.5B-Instruct 这类 Transformers 文本生成模型的本地推理演示。

6. **快速评测与排行榜**

   项目实现了面向课堂演示的快速评测功能。当前快速评测聚焦 Qwen2.5 类型生成式语言模型，使用 C-Eval 20 题样本进行测试，并把准确率写入生成式大语言模型排行榜。排行榜页面可以展示模型、正确数、准确率、数据集和提交版本。

7. **实验追踪与 MLOps 雏形**

   项目集成了 MLflow Tracking Server，并在模型页提供 MLflow 相关信息展示与仓库绑定能力。这说明平台不仅关注模型文件本身，也开始覆盖实验记录、指标追踪和模型评测过程管理。

8. **智能助手与平台知识问答**

   平台实现了站内智能助手。助手可以回答平台使用相关问题，也可以调用站内搜索接口查找模型和数据集。知识来源主要来自 `docs/platform-knowledge/` 目录，形成了一个简化的 RAG 检索问答流程。配置 DeepSeek API Key 后，系统还可以用大模型整理最终回答；未配置时也能返回本地检索结果。

9. **本地部署和演示环境**

   项目使用 Docker Compose 组织本地演示环境，包含前端、后端、PostgreSQL、MinIO、LakeFS、Valkey、Meilisearch 和 MLflow 等服务。通过 Nginx 对前端页面和后端 API 进行统一代理，适合课堂或答辩现场快速启动演示。

整体来看，本项目已经从“模型资源展示网站”扩展成一个具有模型托管、数据集管理、在线运行、快速评测和智能检索能力的中文 AI 模型社区平台。它适合作为课程大作业的完整原型进行汇报。

## 三、实际使用的技术栈

### 1. 后端技术栈

后端主体使用 **Python + FastAPI**。FastAPI 负责提供 REST API，并将不同业务拆分为多个路由模块，例如用户认证、仓库管理、文件管理、搜索、在线运行、评测、MLflow、智能助手和管理后台接口。

后端主要技术包括：

- **FastAPI**：构建 Web API，适合类型清晰、接口较多的后端服务。
- **Pydantic**：定义请求和响应数据结构，保证接口输入输出更规范。
- **Peewee ORM**：管理数据库模型，例如用户、仓库、文件、提交记录、评测记录等。
- **PostgreSQL / SQLite**：开发和演示环境中支持不同数据库后端，Docker 演示主要使用 PostgreSQL。
- **Uvicorn**：运行 FastAPI 应用。
- **httpx / aiohttp**：用于后端内部 HTTP 调用，例如访问 MLflow 或其他服务。

选择 FastAPI 的原因是它开发效率高、接口结构清晰、自动生成 API 文档，适合课程项目中展示系统能力。Peewee 相对轻量，便于快速实现实体关系和数据库迁移。

### 2. 前端技术栈

前端使用 **Vue 3 + Vite**。项目分为用户前台和管理后台两个前端应用：

- `src/cn-model-hub-ui/`：用户前台，包含首页、模型、数据集、空间、排行榜、智能助手、登录注册和资源详情页。
- `src/cn-model-hub-admin/`：管理后台，包含用户、仓库、存储、缓存、健康状态等管理页面。

前端主要技术包括：

- **Vue 3**：构建单页应用，适合组件化开发。
- **Vite**：提供快速构建和开发体验。
- **Element Plus**：提供表单、按钮、表格、标签、提示等常用 UI 组件。
- **UnoCSS / 图标库**：用于快速编写界面样式和图标。
- **Axios**：封装前端 API 请求。

选择 Vue + Vite 的原因是开发速度快、组件组织清晰，非常适合模型列表、详情页、后台表格和表单这类平台型界面。

### 3. 文件存储和版本管理

模型和数据集通常包含大文件，因此项目没有简单地把文件放在后端目录或数据库中，而是采用了更接近真实模型社区的存储方案。

主要组件包括：

- **MinIO / S3**：负责保存模型权重、数据文件等对象。
- **LakeFS**：在对象存储之上提供仓库、分支、提交和版本管理能力。
- **LFS 风格处理**：对大文件进行对象化存储和指针管理，适合模型权重等大体积文件。

这种设计使平台可以同时支持文件上传下载、版本记录、提交历史和大文件管理，更符合模型社区平台的实际需求。

### 4. 搜索、缓存和智能检索

项目使用 **Meilisearch** 实现站内资源搜索，支持模型、数据集和 Space 的检索。搜索逻辑中包含中文关键词扩展和模型别名映射，提升中文场景下的搜索体验。

缓存层使用 **Valkey / Redis 协议**。缓存主要用于提升部分接口和底层数据访问的性能，降低频繁访问 LakeFS 或数据库带来的压力。

智能助手部分结合了：

- 平台知识库文档：`docs/platform-knowledge/`
- 资源搜索接口
- RAG 检索逻辑
- 可选 DeepSeek 模型整理回答
- 中文 embedding 模型配置：`BAAI/bge-small-zh-v1.5`

这使助手既可以回答“平台怎么用”，也可以帮助用户查找模型和数据集。

### 5. 在线 Demo 和快速评测

在线 Demo 运行部分使用 **Python 子进程 + Gradio + Transformers**。

当用户启动模型 Demo 时，后端会从 LakeFS 中同步当前仓库版本的文件，然后启动一个本地 Python 运行环境。如果仓库中提供 `app.py`，系统优先运行该应用；如果没有，则可以使用内置 Qwen2.5 Demo 模板。前端通过 iframe 展示 Gradio 页面，并提供运行状态和日志信息。

快速评测部分使用：

- **Transformers**：加载本地托管的 Qwen2.5 模型。
- **C-Eval 20 题样本**：作为课堂演示用的快速评测数据。
- **EvaluationRun 数据表**：记录评测状态、正确数、准确率、提交版本和结果详情。
- **排行榜页面**：按准确率展示生成式大语言模型排名。

这里需要注意：当前快速评测是演示性质的 20 题样本，不应宣传成完整 C-Eval 官方评测结果。

### 6. 实验追踪和部署

项目集成 **MLflow Tracking Server**，用于展示实验追踪能力。当前平台已经可以检查 MLflow 服务状态，并支持模型仓库绑定 MLflow experiment，为后续记录训练参数、评测指标和 artifact 做准备。

部署方面使用：

- **Docker Compose**：统一编排前端、后端、数据库、对象存储、搜索、缓存和 MLflow 服务。
- **Nginx**：承载前端静态页面，并将 `/api/`、`/admin/api/` 等请求代理到后端。
- **Cloudflare Tunnel**：可用于临时公网演示，把本地 `28080` 端口暴露给外部访问。

这种部署方式不等同于生产环境，但非常适合课程演示：一台电脑即可启动完整平台，并能临时通过公网链接展示。

## 四、系统功能概览

### 1. 首页和资源导航

平台首页展示中文开源 AI 模型社区的定位，并提供模型、数据集、空间、排行榜和智能助手等入口。首页也会展示资源统计和排行榜摘要，使用户可以快速了解平台内已有资源。

这一部分适合在 PPT 中作为项目整体成果展示，用截图说明平台已经具备完整的前台入口。

### 2. 模型社区功能

模型模块是项目的核心。用户可以创建模型仓库、上传模型文件、维护 README、查看文件树和提交记录。模型页还会展示下载量、点赞数、公开状态、相关资源、MLflow 信息以及 Demo / 评测入口。

对于课程汇报，可以笼统表述为：项目实现了模型资源的托管、展示、下载、版本管理和运行入口，具备一个模型社区平台的基本形态。

### 3. 数据集管理功能

数据集模块用于托管训练集、评测集或演示数据。当前项目支持数据集仓库、README 展示和结构化数据预览能力。C-Eval 数据集也被作为中文评测场景中的示例资源使用。

汇报时可以强调：模型社区不仅管理模型文件，也能管理配套数据集，为后续训练、评测和复现实验提供基础。

### 4. Space 与在线 Demo

Space / Demo 功能用于让用户直接体验模型运行效果。当前实现不是完整云平台，而是一个面向课程演示的本地运行系统。它可以从平台仓库中同步模型文件，启动 Gradio Demo，并把运行页面嵌入前端。

汇报时建议这样表达：项目实现了“简化版在线 Demo 运行流程”，可以展示平台托管模型如何被实际加载和运行。

### 5. 搜索与资源发现

项目实现了中文搜索能力，支持资源关键词检索和中文模型别名扩展。用户可以通过模型列表、数据集列表或智能助手寻找资源。

这一功能对应课程作业中“社区资源发现”和“模型检索”的要求。汇报时可以强调中文场景的适配，而不是只说普通关键词搜索。

### 6. 快速评测与排行榜

平台提供面向中文大模型的快速评测链路。用户可以对 Qwen2.5 类型模型发起 C-Eval 20 题快速评测，系统记录结果并在排行榜中展示。

这一部分是项目比较有亮点的地方，因为它把“模型托管”进一步延伸到“模型能力评价”。虽然当前评测规模较小，但已经形成了从模型上传、模型运行、模型评测到排行榜展示的完整闭环。

### 7. 智能助手

智能助手主要承担两个角色：一是回答平台使用问题，二是辅助搜索模型和数据集。它会检索平台知识库，也能调用站内搜索接口。配置大模型后，可以对检索结果进行更自然的整理。

汇报时可以把它理解为平台的“使用向导 + 资源检索助手”，不需要把它包装成通用聊天机器人。

### 8. 管理后台

项目包含独立的管理后台，用于查看和管理用户、仓库、存储、缓存、健康状态、凭据和邀请等内容。管理后台体现了平台作为一个完整系统的运维能力。

这部分不需要在 PPT 中展开太多，可以作为系统完整性的补充说明。

## 五、系统架构说明

项目整体采用前后端分离架构。

用户通过浏览器访问前端页面，前端由 Nginx 提供静态文件服务。涉及数据操作时，前端通过 API 调用 FastAPI 后端。后端根据不同功能访问 PostgreSQL、LakeFS、MinIO、Meilisearch、Valkey 和 MLflow 等服务。

整体架构可以概括为：

```text
浏览器
  ↓
Nginx 前端服务
  ↓
FastAPI 后端
  ├─ PostgreSQL：用户、仓库、文件、评测等元数据
  ├─ LakeFS：模型和数据集的版本管理
  ├─ MinIO/S3：模型权重和数据文件对象存储
  ├─ Meilisearch：站内中文搜索
  ├─ Valkey：缓存
  ├─ MLflow：实验追踪
  └─ Python/Gradio Runtime：在线 Demo 运行
```

这个架构的优势是职责比较清晰：前端负责展示和交互，后端负责业务逻辑，数据库保存结构化元数据，对象存储保存大文件，LakeFS 提供版本管理，搜索和缓存作为独立服务增强平台能力。

## 六、可以在 PPT 中突出的亮点

1. **不是简单 CRUD，而是模型社区完整原型**

   项目不仅有用户、列表、详情和上传下载，还加入了模型运行、评测、排行榜、智能助手和实验追踪等 AI 平台特色能力。

2. **面向中文模型生态**

   项目主题、页面文案、搜索别名、C-Eval 评测和 Qwen2.5 Demo 都围绕中文模型场景展开，不是简单复制通用模型平台。

3. **大文件和版本管理设计比较贴近真实场景**

   模型权重和数据文件通过 MinIO/S3 保存，版本和提交由 LakeFS 支撑，比普通文件上传更适合模型社区。

4. **形成了演示闭环**

   可以从首页进入模型，查看模型卡片和文件，启动 Demo，进行快速评测，再查看排行榜和智能助手。这条链路适合课堂汇报展示。

5. **部署结构完整**

   Docker Compose 中包含前端、后端、数据库、对象存储、版本管理、搜索、缓存和实验追踪服务，说明项目不是只有前端页面，而是一个多服务系统。

## 九、总结表述

可以在汇报结尾这样总结：

> 本项目实现了一个面向中文开源 AI 模型生态的社区平台原型。平台以模型和数据集仓库为核心，支持资源上传下载、版本管理、中文搜索、在线 Demo、快速评测、排行榜、MLflow 实验追踪和智能助手。系统采用 FastAPI + Vue 前后端分离架构，并结合 PostgreSQL、MinIO、LakeFS、Meilisearch、Valkey、MLflow 和 Docker Compose 构建完整演示环境。虽然当前仍是课程级 MVP，但已经形成了从模型托管到运行体验、从快速评测到资源检索的完整功能闭环。
